# Manual review checklist

These are the things the automated tests can't judge. Tick them on a real phone and a real laptop.

## Feel and wording
- [ ] Take it cold, as a friend would. Does any twist feel like a trick played on you rather than a lesson? Note which one.
- [ ] Does the results screen feel like a mirror, not a grade? Is any line preachy?
- [ ] Is the authority wording ("you rated this false claim likely") fair, not accusing?
- [ ] AQ-10 result text: calm, not alarming, and clearly not a diagnosis?

## Smoothness
- [ ] Every tap answers at once, with no lag between choosing and the Next button enabling.
- [ ] Screen changes fade in without a jump or flash, in Safari on iPhone too.
- [ ] Results scroll smoothly on an older phone, and opening a moment doesn't shift the page.
- [ ] Turning on Reduced motion in Settings or the OS removes the fades.

## Looks
- [ ] Light and dark on a real screen: the blues for Authority, Crowd and Instructions are told apart at a glance, and the terracotta reads as a different family.
- [ ] Large text (Settings, and iOS Dynamic Type through Safari zoom) doesn't clip.
- [ ] Icon is recognisable as a browser tab favicon and on an iPhone home screen (Share → Add to Home Screen).

## Assistive tech
- [ ] VoiceOver on Mac and iPhone: each question, its options and the progress are announced. The results moments open with VO+Space.

## Live services
- [ ] The GitHub Pages link loads on mobile data. Fonts fall back cleanly when offline.
- [ ] Copy-link works in Safari, Chrome and Firefox, and the link opens the friend view.
- [ ] Every source link in the results opens the right page.
- [ ] Feedback tab opens a new GitHub issue.
